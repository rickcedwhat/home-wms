Key engineering patterns and talking points for Cedrick's upcoming rounds.

Why Node.js Middleware in Front of NetSuite?

              
    
                
  • Absorb High-Throughput Burst Traffic: Warehouse scanners scan continuously (thousands of scans/minute). NetSuite ERP has strict concurrency throttles and concurrency governance units per account.
    • 
                
  • Sub-20ms Latency: In-memory caching avoids repetitive 300ms cloud ERP roundtrips on repeated SKU/Bin checks.
    • 
                
  • Edge Concurrency Control: Mutex queueing in middleware serializes simultaneous worker picks on the same bin, preventing database deadlock.
    • 
                
  • Error Normalization: Translates cryptic NetSuite SuiteScript errors (e.g. INSUFFICIENT_INVENTORY_IN_BIN) into instant, clear messages.
    • 
              

            


            

              
🔐

              
NetSuite Token-Based Auth (TBA / RFC 5849)

              
    
                
  • HMAC-SHA256 OAuth 1.0a: NetSuite RESTlets authenticate each request using signed headers rather than passing plaintext passwords or simple bearer tokens.
    • 
                
  • Signature Base String: Combines HTTP Method + Normalized Endpoint URL + Lexicographically sorted parameters (Consumer Key, Token ID, Nonce, Timestamp).
    • 
                
  • Replay Attack Prevention: Nonces and timestamp windows ensure intercepted headers cannot be replayed by bad actors on warehouse Wi-Fi.
    • 
              

            


            

              
⚙️

              
SuiteScript 2.1 AMD Module Anatomy

              
    
                
  • AMD Define Pattern: define(['N/record', 'N/search', 'N/error'], function(record, search, error) { ... }).
    • 
                
  • N/record Dynamic Mode: Uses record.create({ type: 'bintransfer', isDynamic: true }), selectNewLine(), setCurrentSublistValue(), and commitLine().
    • 
                
  • Atomic Commitment: Changes only update ERP ledgers once record.save() completes successfully.
    • 
              

            


            

              
🔄

              
Knockout.js MVVM vs. React Mental Model

              
    
                
  • Observables vs State: ko.observable(val) is an accessor function: call val() to read, val(newVal) to write. React uses [val, setVal] tuples.
    • 
                
  • Automatic Dependency Tracking: ko.computed automatically tracks whatever observables are read inside its evaluator during execution—no manual React dependency array needed.
    • 
                
  • Fine-Grained DOM Updates: Knockout surgically mutates only the specific text node or attribute subscribed to the observable without virtual DOM diffing or full component re-rendering.
